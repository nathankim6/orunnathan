# 선생님 기억 (teacher-memory)

ORUN ORACLE(`public/orun-oracle.html`)과 같은 개념 — 문항 데이터화 → 지문 매칭 → 출제
성향 프로파일 학습 → 예측 → 적중 모의고사 — 을 웹앱 없이 `teacher-memory/` 폴더와 이
대화만으로 한다. 데이터화·서술·예측·출제는 API 를 부르지 않고 **Claude 가 직접** 한다.
숫자(비율·평균·빈도)만은 반드시 `scripts/count_stats.py` 로 세어서 낸다.

전체 구조와 원칙은 `teacher-memory/README.md` 를 먼저 읽는다.

## 절차

### 0. 선생님 폴더 찾기/만들기

`teacher-memory/schools/<학교-슬러그>/teachers/<선생님-슬러그>/` 가 그 선생님의 폴더다.
없으면 새로 만든다 — 학교 이름은 로마자 슬러그로(`heukseok-go`), 선생님은 이름 로마자
슬러그로(`yoon-eunyoung`). 폴더를 만들면 `info.md` 를 먼저 쓴다:

```md
# 윤은영 (yoon-eunyoung)

- 학교: 흑석고
- 과목: 영어A
- 학년: 1학년
- 등록일: 2026-09-19
- 메모: (강사가 알려준 배경 — 재직 연차, 전임/기간제, 특이사항 등)
```

같은 답으로 `profile.md` 도 빈 틀로 만든다(§3 참고, "아직 학습 전"으로 시작).

### 1. 자료 입력 — 원문은 그대로 보존

사용자가 기출/시험범위/프린트를 텍스트로 붙여넣거나 파일로 주면, **요약·의역 없이 원문
그대로** 아래에 저장한다. 스캔 이미지·PDF 라면 먼저 `scan-to-text` 스킬로 텍스트를 뽑는다.

- 기출 → `sources/exams/<연도>-<학기>-<시험명>.md` (예: `2025-1-중간.md`)
- 시험범위 → `sources/scope/<연도>-<학기>.md`
- 선생님 프린트 → `sources/handouts/<식별 가능한 이름>.md`

각 파일 맨 위에 한 줄 메타를 적는다: `date:`, `label:`(사람이 읽을 이름) 등 알아본 대로.

### 2. 문항 데이터화 (기출을 넣었을 때만)

기출 원문을 문항 단위로 쪼개 `questions/<연도>-<학기>-<시험명>.json` 에 쓴다. 스키마:

```json
{
  "examId": "2025-1-중간",
  "examLabel": "2025학년도 1학기 중간고사",
  "date": "2025-04-25",
  "totalPoints": 100,
  "questions": [
    {
      "order": 1,
      "type": "빈칸",
      "subtype": "",
      "format": "객관식",
      "difficulty": "중",
      "points": 3,
      "passageId": "p1",
      "external": false,
      "grammarPoints": [],
      "vocabPoints": [],
      "subjectiveConditions": [],
      "stem": "다음 글의 빈칸에 들어갈 말로 가장 적절한 것은?"
    }
  ]
}
```

필드 뜻:
- `type` — 유형. 일관되게 쓴다: 주제·제목·요지·주장·함의·빈칸·어휘·어법·순서·삽입·지칭·
  일치불일치·요약·장문·서술형 등. 새 유형이 나오면 만들어 쓰되 이후에도 같은 이름을 쓴다.
- `format` — `객관식` | `서술형`.
- `difficulty` — `상` | `중` | `하`. 원문에 난이도 표시가 없으면 문항 내용·배점으로 판단.
- `passageId` — 같은 지문을 공유하는 문항은 같은 id (예: 17~19번이 한 지문이면 셋 다 `p1`).
  지문이 없는 독립 문항(어법 단독 등)은 생략.
- `source` — 지문 출처를 적는다. 가능하면 자료에 찍힌 태그 그대로(`올림포스6강-4`, `교과서4과-1`,
  `NY Times 2-1`). 직전보충 같은 대비자료에는 지문마다 출처 태그가 있으니 **먼저 거기를 본다** —
  시험지만 보고 어림으로 분류하면 틀린다(한 번 교과서 4과를 3과로 잘못 보고 담당 선생님을 바꿨다).
- `category` — 지문 출처를 **세 갈래 중 하나**로 적는다(사용자 용어). `external` 은 여기서 따라 나온다.
  · **`교과서`** — 교과서 본문·Further Reading
  · **`부교재`** — 올림포스 등 범위에 공지된 문제집 (모의고사 지문도 여기로 통칭한다)
  · **`외부지문`** — 소설·신문 기사처럼 밖에서 끌어온 글 (EPICAC, NY Times)
  부교재를 외부로 세지 않는다. 둘을 섞으면 "범위만 돌면 되는 선생님"과 "밖에서 지문을
  가져오는 선생님"이 뒤바뀌어 예측이 통째로 어긋난다.
- `external` — `category == "외부지문"` 이면 `true`, 아니면 `false`.
  **주의: 외부지문이라고 학생이 처음 보는 글이라는 뜻이 아니다.** 흑석고는 외부지문도
  시험 전에 프린트로 배부한다. "외부"는 출처가 교과서·부교재 밖이라는 뜻일 뿐이다.

`count_stats.py` 가 이 `category` 로 **교과서 출제비율**을 시험별·누적으로 낸다
(`textbookRatio` · `sourceMix` · 시험별 `sourceCount`). 선생님마다 교과서에서 몇 문항을
떼는지가 아주 안정적인 지표라 매 시험 갱신한다.
- `grammarPoints` / `vocabPoints` — 어법·어휘 문항이 다루는 포인트. 프로파일의 "자주 나오는
  어법 포인트" 통계가 여기서 나온다.
- `subjectiveConditions` — 서술형 문항의 조건문 그대로(예: "단어 5개 이내로", "본문 표현을
  그대로 활용하여"). 서술형 습관 분석의 재료.
- `answer` — 정답(선택). `"⑤"`, 복수 정답은 `"③,⑤"`. 정답지가 없으면 Claude 가 직접 풀어 적고,
  풀이 근거는 `sources/exams/*.md` 의 해당 문항 아래 "정답(풀이)" 줄에 남긴다.

문항 수가 많아도 빠짐없이 전부 데이터화한다 — 일부만 넣으면 통계가 왜곡된다.

### 3. 프로파일 갱신 — `profile.md`

**절대 덮어쓰지 않는다.** 파일 맨 위에 새 버전을 추가하고, 예전 버전은 그 아래
"이전 버전" 섹션으로 밀어 보존한다(지우지 않는다).

1. 숫자를 낸다:
   ```sh
   python3 teacher-memory/scripts/count_stats.py teacher-memory/schools/<학교>/teachers/<선생님>
   ```
2. 그 결과(JSON)를 근거로 서술을 쓴다 — 숫자는 스크립트 값 그대로 인용하고, "왜 이런
   경향인가", "다른 학년/타 학교 평균과 비교해 두드러지는 점"처럼 스크립트가 낼 수 없는
   해석만 직접 판단해 덧붙인다.
3. `profile.md` 맨 위에 다음 형식으로 새 버전을 쓴다:

```md
# 윤은영 — 출제 성향 프로파일

## v2 — 2026-09-19 (근거: 시험 2개 · 문항 8개)

**요약**: (2~4문장 — 이 선생님의 출제 스타일을 가장 잘 드러내는 특징)

- 문항 구성: 객관식 75% · 서술형 25%, 시험당 평균 4문항
- 유형 비중: 빈칸 37.5% · 어법 25% · 서술형 25% · 주제 12.5%
- 난이도: 상 62.5% · 중 37.5% — 상 비중이 높은 편
- 어법 포인트: 분사구문(2회) > 관계대명사(1회)
- 서술형 조건: "단어 5개 이내" 반복 등장 — 정형화된 조건문을 선호
- 외부지문 비중: 50%
- **지난 판(v1) 대비 달라진 점**: (v1이 있으면 트렌드 요약, 없으면 "첫 프로파일")

<details><summary>이전 버전</summary>

## v1 — 2026-08-01 (근거: 시험 1개 · 문항 4개)
...
</details>
```

버전 번호는 1부터 순서대로 올린다. 자료를 추가할 때마다(기출 한 건이라도 늘 때마다)
갱신하는 게 기본이다 — 사용자가 "나중에" 라고 하지 않는 한 자료를 받은 김에 바로 올린다.

### 3½. 페르소나 갱신 — `persona.md`

`persona.md` 는 그 선생님의 **1인칭 출제 규칙**이다("나는 윤은영이다 …"). 예측과 출제는
이 파일을 읽고 **그 선생님이 되어서** 한다(§4·§5). 프로파일을 새 판으로 올렸으면 페르소나도
같이 고친다 — 둘이 어긋나면 프로파일(숫자)이 맞고 페르소나를 맞춘다.

페르소나에 들어갈 것: 나는 누구인가 · 출제 원칙(고정 뼈대 — 교과서 몇 문항을 어떤 유형으로) ·
**지문을 받으면 어떻게 읽는가**(지문 특징 → 유형 표) · 발문 말투 · 선지 만드는 법 · 배점 ·
**아직 안 낸 유형 중 낼 법한 것** · 하지 않는 것. **모든 규칙 뒤에 근거 문항 번호를 단다.**
근거 없는 성격 묘사("꼼꼼한 분")는 쓰지 않는다.

### 4. 예측 — `predictions/<날짜>-v<n>.md`

프로파일이 최소 2개 시험 이상을 근거로 할 때부터 의미가 생긴다(1개뿐이면 "아직 예측
근거 부족" 이라고 말하고 만들지 않는다).

**그 선생님이 되어서 한다.** 먼저 `persona.md` 를 읽고, 이번 범위의 지문(교과서·부교재·
외부지문 프린트 전부)을 **한 편씩 그 선생님의 눈으로 읽는다.** 순서 —

1. **지문 풀을 확정한다.** 흑석고는 외부지문까지 시험 전에 프린트로 배부한다 — 범위 공지·
   직전보충 자료에 있는 지문이 곧 후보 전부다(2026 1학기 기말 커버리지 100%, 직보 31지문 중
   24지문 출제). 자료가 없으면 예측보다 자료 확보를 먼저 요청한다.
2. **고정 뼈대를 먼저 앉힌다.** 페르소나의 출제 원칙대로 교과서/부교재/외부지문에서 각각 몇 문항,
   그중 어떤 유형이 고정인지(예: 윤은영 교과서 3 = 어법 1 · 어휘 1 · 독해 1).
3. **지문마다 유형을 정한다 — 지문의 특징이 유형을 부른다.** 과거 유형 분포를 그대로 복사하지
   않는다. 페르소나의 "지문을 받으면 나는 이렇게 읽는다" 표를 기준으로, 이 지문의 뼈대
   (결론 일반화 문장 · 양면 대조 · 예시 나열 · 담화표지 · 비유 · 같은 대상의 다른 이름 ·
   인물 여럿의 견해 …)를 보고 그 선생님이 붙일 유형을 고른다.
4. **기존에 안 나온 유형도 예측해도 된다.** 지문 특성이 그 유형을 강하게 부르고, 페르소나의
   원칙(범위 · 세트 여부 · 서술형 여부 등)을 어기지 않으면 새 유형을 낸다. 이때 반드시
   **`[신규 유형]`** 표시와 함께 **"이 지문의 어떤 특징이 이 유형을 부르는가"**를 한 줄로 적는다.
   페르소나의 "아직 안 낸 유형" 표에 가능성이 적혀 있으면 그것을 따른다.
5. 지문별 예측을 모아 **문항 번호 순서·배점·난이도**까지 채운 청사진을 만든다.

청사진에 들어갈 것:
- 지문별 표: 지문(출처 태그) · 예상 유형 · 근거(지문 특징 + 과거 유사 문항 번호) · `[신규 유형]` 여부
- 출제 안 될 것 같은 지문과 그 이유
- 예상 어법 포인트 · 어휘 바꿔치기 후보(교과서는 워크시트 어휘목록에서)
- 신뢰도 — 근거 시험 수가 적으면 낮게 표시하고 왜 낮은지 적는다

### 5. 적중 동형모의고사 — `mock-exams/<날짜>-v<n>.md`

**그 선생님이 되어서 문항을 쓴다.** 예측 청사진대로, 페르소나의 발문 말투·선지 만드는 법·
오답 설계(예: 윤은영 "4 대 1 극성", 전정이 "그럴듯한 과잉 해석")·배점을 그대로 따른다.
지문은 범위 원문·프린트에서 가져오고, 교과서 어휘 문항은 워크시트 영영풀이를 쓴다.
공동 출제 시험이면 두 선생님 몫을 각자 페르소나로 따로 만든 뒤 실제 시험지 순서대로 합친다.
파일 하나에 문제지 전체 + 정답/해설을 함께 담고, 해설에는 문항마다 "왜 이 선생님이라면 이렇게
냈을까"(근거 기출 번호)를 한 줄 붙인다(화면에 보여줄 때는 정답란을 접어 스포일러 없이 보여준다).

사용자가 화면에서 바로 보고 싶어하면 이 마크다운을 그대로 응답에 옮겨 보여주고,
인쇄/워드가 필요하면 그때 형식을 물어본다(이 스킬은 텍스트 산출까지만 — DOCX 변환이
필요하면 `orun-docs` 류 스킬과 별도로 조합한다).

### 6. 실제 시험이 나오면 — 예측을 채점한다

예측했던 시험의 기출이 들어오면, 데이터화(§2)와 함께 **예측 청사진과 실제를 대조**해
`predictions/` 의 그 파일 끝에 적중표(지문 적중 · 유형 적중 · 신규 유형 적중)를 붙이고,
빗나간 것은 페르소나의 어느 규칙이 틀렸는지 찾아 고친다. 이것이 페르소나가 배우는 길이다.

## 지켜야 할 것

- **덮어쓰지 않는다.** `profile.md` 버전, `sources/` 원문, `questions/*.json` — 전부 추가만
  하고 지우지 않는다. 잘못 넣은 게 있으면 사용자에게 확인 후 수정하되, 실수였다는 걸
  커밋 메시지에 남긴다.
- **숫자는 스크립트로.** `count_stats.py` 를 거치지 않은 비율·평균을 profile.md 에 쓰지
  않는다.
- **원문은 원문대로.** 데이터화(JSON)는 분석용 축약이지, 원문(`sources/`)을 대체하지
  않는다. 원문을 지우거나 요약으로 바꾸지 않는다.
- **선생님끼리 섞지 않는다.** 다른 선생님 자료를 잘못된 폴더에 넣지 않는다. 헷갈리면
  사용자에게 어느 선생님인지 먼저 확인한다.
- **커밋한다.** 자료를 넣거나 프로파일을 갱신했으면 `teacher-memory/` 변경분을 커밋한다.
  푸시는 사용자가 쓰는 브랜치 관례를 따른다(자동 배포 대상이 아니므로 `main` 머지는
  필요 없다).
